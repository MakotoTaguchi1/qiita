# はじめに

唐突ですが、最近読んで良かった本をまとめてみました。

筆者のスペックとしては、以下のような感じです。

- エンジニア歴 6 年で、Web 領域のフルスタックエンジニアやリードを担当することが多い
- 現在はフリーランスで業務委託参画中
- 最近は AI の台頭もあり PM 領域やスタートアップにも関心が出てきた

エンジニアになってから本は継続的に読んでいるので、自身の振り返りのためにも書いてみた次第です。
同じような暦感の方には参考になるかもしれないです！

# よかった本

### 1. 『Software Design』 年間購読（サブスク）

いきなり本というより雑誌で、しかも購読ですが、、
ただ、おすすめ度が高いので最初に持ってきました。

https://www.fujisan.co.jp/product/1535/

**紙版がおすすめ**です。雑誌らしく気軽にパラパラとめくってつまみ食いできるためです。

**毎月自動で配達されるので本屋に買いにいく必要もない**し、個別購入より 1000 円 くらい安くなります。

自分のそのときの興味に関係なくランダム性があり、知識の全体補強になるので、すごく重宝しています。
「慣れ親しんでいるが実は理解が浅い・忘れている技術」の学び直しや新しいツールのキャッチアップを**持続的・半強制的**にできます。

例えば最近の号では、以下が面白かったです

```
- 『ORM で学ぶ Web 開発のベストプラクティス』:
   ORM は単なる SQL 生成器ではなく、オブジェクト指向プログラミングと RDB の間にあるギャップを吸収してくれているという色々な側面での説明が興味深かった
- 『AWS 活用ジャーニー第 45 回 実は色々できる Amazon S3』:
   S3 Vectors というベクトルバケットの存在を初めて知った
- 『AI が書いたコード、どうテストする？』:
   AI 駆動でも仕様書をそのままテストケースにしてはいけない・ステークホルダーとの会話など人間が学習する工程の必要性など、前提や注意点を知ることができ有益だった
```

私はその月の Software Design はリビングに置いています。そして朝起きてご飯を食べる前や、休日の暇なタイミングに読むことが多いです。

### 2. 『生成 AI「思考」の裏側』

AI エージェントを日々よく使っているが、あまり裏側の仕組みを知らない・知りたいと思っている方向けに、一番最初の本としておすすめです。

https://bookplus.nikkei.com/atcl/catalog/25/10/09/02257/

技術書ではなく一般人向けで、難しい式も出てこないです。
（理系だが数学がすごく苦手だった私も、抵抗少なく完読することができました。）

また読んだのが年末年始で時間もあったため、知識定着のために記事も書いてみました ↓

https://qiita.com/MAKOTO1995/items/44da29e6d73ff8c84b6d

こちらの本を読み込むことで「推論・学習」「自然言語処理」「ベクトル」「Transformer」のような、なんとなく聞いたことあるくらいの言葉を、つながりを持って理解することができました。

### 3. 『OpenID Connect 入門』

これは完全に私のタイミングと知識レベルに合った本でした。

https://gihyo.jp/book/2026/978-4-297-15456-1

実務でちょうど、ネイティブアプリに Auth0 を使って認証を組み込むところの担当になって AI エージェントと設計を壁打ちしている時期がありました。
当初、認証周りを体系的に理解できておらず、AI の提案に対して良し悪しが判断できないなーと悩んでいたところ、ちょうど本屋でこちらの本を見つけました。

こちらの本は Auth0 というワード自体は出てこないものの、Auth0 が対応する認可・認証の標準仕様である OAuth 2.0 や OpenID Connect（OIDC）について説明があり、**図も多くてイメージで理解しやすかった**です。

認可コードフローの種類や、ネイティブアプリ・BFF を例にした説明など、ちょうど実務で欲しかった情報が載っていたため、すぐに生かすことができました。本当に感謝です。

### 4. 『Running LEAN』

友人の起業・初期開発に関わっていた時期があったので、スタートアップ系の本を読み漁っていました。
そのなかで、一番印象に残っていた本がこちらでした。

https://www.oreilly.co.jp/books/9784814400263/

（ただ、オライリー本かつ 300 ページ以上あるので、さすがに全部は読んでません）

こちらの本は、グロースより前の**顧客の課題発見から MVP による検証、PMF を目指すまでのフェーズ**も含めて扱っています。
**プロダクトマネジメント系の日本語の本で、このあたりを扱ったものは現状少ない認識で、貴重です。**

```
- ソリューションではなく課題にフォーカスしろ
- MVP をいきなり作るのではなく、MVP を「定義」してデモを先に作り、検証する時間をとれ
```

といった、イントロダクションから個人的に刺さる内容が連発していました。

ところどころ差し込まれる NOTE や TIPS も発見になるものが多かったです。

**特にエンジニアが起業初期に落とし穴にはまらないためのマインドセットを培う**ことができると思います。
（私も以前やっていた個人開発でも見事にアンチパターンを踏んでしまっていました。もっと早く出会いたかった、、）

# まとめ

すごく中途半端な時期ですが、最近読んだ本を振り返ってみました。

よかった本リスト

- 『Software Design』 年間購読（サブスク）
- 『生成 AI「思考」の裏側』
- 『OpenID Connect 入門』
- 『Running LEAN』

個人的には AI の台頭やキャリア状況的に、純粋な技術書よりスタートアップ・マネジメント系の本を読むことが増えている傾向がありました。
ただ、エンジニアとしてはまず技術力が第一なので、Qiita や Zenn による情報収集だけでなく、技術書ももっと読んで体系的に理解したり、技術記事を書いて思考を深めることも意識的にやっていこうと思いました。
